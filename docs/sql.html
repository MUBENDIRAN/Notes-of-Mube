SQL is the language used to define, change and read data in a relational database. These notes cover types, the core statements, filtering, joins, constraints, views, normalization and transactions. Most of the syntax is MySQL. PostgreSQL and SQL Server use the same ideas, and some of the function names differ.

1. SQL, comments and data types

The notes expand SQL as Structured Query Language and pronounce it “sequel.” Both “sequel” and “S-Q-L” are used. Keywords are not case sensitive: select and SELECT are the same statement. Whether stored text matches in a case-sensitive way depends on the column's collation.

SQL, the DBMS and the database are three different things. The notes chain them as SQL, then DBMS, then database. SQL is the language you write. A DBMS is the software that runs it, such as MySQL. A database is the collection of tables that software stores.

   can span lines */

Character types

Type in the notesWhat it stores
CHAR(10)A fixed length of 10 characters. Shorter values are padded.
VARCHAR(10)A variable length, up to 10 characters. It stores the characters you put in, plus a small length marker.
TEXTA long piece of character data. The notes describe this as saving the content as text.
BLOBA binary large object. The notes use it to store an image as bytes rather than as characters.

Character sets

These statements are MySQL. SHOW CHARACTER SET; lists the character sets the server knows. A column or a whole database can name one:

SHOW CHARACTER SET;

CREATE DATABASE school CHARACTER SET utf8mb4;

CREATE TABLE student (
  name VARCHAR(10) CHARACTER SET utf8mb4
);

The original notes write utf8. In MySQL that name is the older 3-byte encoding. utf8mb4 is the character set that stores the full Unicode range, including characters that need four bytes. Use utf8mb4 for a new database.

2. Databases and tables

StatementPurpose in the notes
DROP DATABASE name;Deletes that database.
DROP SCHEMA name;Deletes a schema. In MySQL, schema and database are two names for the same thing, so this matches DROP DATABASE.
USE name_db;Selects the database the following statements apply to.
SHOW TABLES;Lists the tables in the current database.
DROP TABLE name;Deletes a table.
DROP removes the object. DROP DATABASE and DROP TABLE delete the definition and the rows. They do not ask for confirmation.

The notes give the create-table line as CREATE TABLE name (home datatype Primary Key (18)). That mixes the table name, a column and a length. A table is the name, then a list of columns:

CREATE TABLE home (
  id INT PRIMARY KEY,
  city VARCHAR(18)
);

Changing a table uses ALTER TABLE. The notes add a column, and drop one when that column should go.

ALTER TABLE home ADD pin VARCHAR(6);
ALTER TABLE home DROP COLUMN pin;

The notes write DROP (column) for the second case. The working MySQL clause is DROP COLUMN followed by the column name.

Insert and read

INSERT INTO home (id, city) VALUES (1, 'Chennai');

SELECT * FROM student;

The notes write INSERT INTO home(table) and SELECT (*) FROM Student. The parentheses after INSERT INTO hold column names, not the word table. SELECT * has no parentheses around the star. * means every column.

3. Filtering, update and sort

WHERE keeps the rows that match a condition. The notes combine it with AND, OR, IN, NOT IN and LIKE.

SELECT name, city
FROM student
WHERE city = 'Chennai';

SELECT name
FROM student
WHERE city IN ('Chennai', 'Delhi')
  AND name LIKE 'A%';

LIKE 'A%' matches a value that starts with A. % stands for any sequence of characters. The notes write the pattern as '%...%', which matches the text in the middle of the value as well.

NOT IN does not behave as a simple “exclude this list” when the list contains NULL. A comparison with NULL is unknown, so the whole NOT IN filter can return no rows. Keep NULL out of that list, or use NOT EXISTS.

Update and delete

UPDATE student
SET name = 'Updated name'
WHERE id = 1;

DELETE FROM student
WHERE id = 1;

The notes say delete is similar to update. Both need a WHERE clause unless you mean every row. An UPDATE or DELETE without WHERE changes or removes the whole table.

Distinct and order

KeywordPurpose in the notes
DISTINCTReturns each value once. The notes call this the unique keyword.
ORDER BY column ASCSorts ascending. This is the default when you omit ASC.
ORDER BY column DESCSorts descending.

4. Aggregates, strings, dates and groups

The notes group these as functions that do one specific job. The names below are the MySQL names from the notes.

FunctionResult in the notes
COUNT(*)How many rows.
AVG(score)The average of a numeric column. The notes write AVG(name) as the shape of the call. An average needs numbers, not a name.
SUM(score)The total.
MAX(score)The largest value.
MIN(score)The smallest value.
UCASE(name)The value in upper case. UPPER is the same function.
CHAR_LENGTH(name)How many characters are in the value.
CONCAT(first, ' ', last)The pieces joined into one string.
FORMAT(amount, 0)The number rounded and shown with grouping separators. The notes give 1,00,000 as that kind of display. With no locale argument, MySQL uses en_US, so 100000 becomes 100,000. A locale such as en_IN produces the Indian grouping from the notes.
LEFT(name, 1)The first characters. Here, the first character.

Dates

Type or functionWhat the notes say
DATEA calendar date, written YYYY-MM-DD.
DATETIMEA date and a time you set. The notes call this manual.
TIMESTAMPA date and a time the notes call automatic.
NOW()The current date and time.
DATEDIFF(end_date, start_date)The number of days between two dates, in MySQL.
DATE_ADD(start_date, INTERVAL 1 DAY)One day after that date. The notes also use an interval of 1 month.

Both DATETIME and TIMESTAMP store a date and a time. Automatic filling comes from a default such as CURRENT_TIMESTAMP. MySQL has often applied that default to TIMESTAMP, which is why the notes call it automatic. It is a property of the column definition, not of every TIMESTAMP value.

SELECT NOW();
SELECT DATEDIFF('2026-11-12', '2026-11-01');
SELECT DATE_ADD('2026-11-12', INTERVAL 1 MONTH);

GROUP BY and HAVING

GROUP BY folds rows that share a value, so an aggregate can be computed per group. HAVING filters those groups. WHERE filters rows before the grouping happens.

SELECT city, COUNT(*) AS students
FROM student
WHERE city IS NOT NULL
GROUP BY city
HAVING COUNT(*) > 1;

5. Constraints, keys and indexes

ConstraintMeaning in the notes
NOT NULLThe column must have a value. A null is rejected.
DEFAULTIf an insert does not supply a value, this one is stored.
UNIQUEThe notes say this ignores a duplicate. A unique column rejects the second insert. It does not skip it silently.
AUTO_INCREMENTMySQL fills 1, then 2, then 3 as rows are added, when you omit the value.
PRIMARY KEYThe row's identity. It is unique and not null. The notes note that a unique index is created for it.
FOREIGN KEYA value in this table must match a primary key, or another unique key, in the referenced table. That is how the notes join two tables.
CREATE TABLE student (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(40) NOT NULL,
  email VARCHAR(80) UNIQUE,
  city VARCHAR(40) DEFAULT 'Chennai',
  home_id INT,
  FOREIGN KEY (home_id) REFERENCES home(id)
);

An index is a structure the server uses to find rows without reading the whole table. The notes say a primary key and a foreign key act as an index, and a UNIQUE column is an index too. In MySQL that holds: the primary key is a unique index, a unique constraint creates an index, and InnoDB indexes the columns of a foreign key.

The same page adds the cost. Indexes speed reads and slow writes, because each insert, update and delete also has to maintain those indexes.

ON DELETE

The notes use ON DELETE on a foreign key so that deleting a referenced row does not fail, or so the related rows are handled on purpose. Without an action, MySQL rejects the delete while child rows still point at that parent.

ActionWhat happens to the child rows
ON DELETE RESTRICTThe delete is refused while child rows exist. This is the usual default.
ON DELETE CASCADEChild rows are deleted with the parent.
ON DELETE SET NULLThe foreign key in the child is set to null. That column must allow null.

The action names are the practical forms of the notes' ON DELETE line. CASCADE deletes more than the one row you named. Use it only when those child rows should go too.

6. Joins and UNION

A join reads two tables together by matching the foreign key to the referenced key. The notes describe three results.

JoinWhat the notes keep
INNER JOIN, also written JOINOnly the rows that match. Unmatched rows are left out. The notes call this the perfect join.
LEFT JOINEvery row from the left table. A left row with no match still appears, and the right-hand columns are null.
RIGHT JOINEvery row from the right table, with nulls on the left when there is no match.
SELECT student.name, home.city
FROM student
INNER JOIN home ON student.home_id = home.id;

That query is an illustration of the notes' definition. The original pages do not include this statement.

Which rows survive
INNER JOIN
matches onlyLEFT JOIN
all of the left tableRIGHT JOIN
all of the right table

UNION stacks two results vertically. The notes require the same number of columns and compatible types. UNION removes duplicate rows. UNION ALL keeps them. UNION ALL is not in the original list.

SELECT city FROM home
UNION
SELECT city FROM campus;

7. Subqueries and views

A subquery is a query inside another query. The notes show this shape:

SELECT * FROM student
WHERE name (SELECT name FROM student
            WHERE name = '...');

That line is missing the comparison. The name has to be tested against the inner result with IN or =:

SELECT * FROM student
WHERE name IN (
  SELECT name FROM student
  WHERE name = 'Ada'
);
KeywordMeaning in the notes
EXISTSThe outer query keeps a row when the subquery returns something. The notes say “non-null.” EXISTS checks that at least one row comes back. A row whose columns are null still counts as a row.
ANYThe comparison succeeds if it is true for at least one value from the subquery.
ALLThe comparison succeeds only if it is true for every value from the subquery.
SELECT * FROM home h
WHERE EXISTS (
  SELECT 1 FROM student s
  WHERE s.home_id = h.id
);

SELECT * FROM result
WHERE score > ALL (
  SELECT score FROM result WHERE subject = 'SQL'
);

The EXISTS and ALL statements are illustrations. They are not copied from the original notes. > ALL means greater than every score in that subject. > ANY would mean greater than at least one of them.

Views

A view stores a query under a name, so you can read that result without repeating the full statement. It is not a second copy of the table.

CREATE VIEW chennai_students AS
SELECT name, city
FROM student
WHERE city = 'Chennai';

CREATE OR REPLACE VIEW chennai_students AS
SELECT name
FROM student
WHERE city = 'Chennai';

CREATE OR REPLACE VIEW is the notes' way to change the query of a view that already exists.

8. Normalization, transactions and ACID

Normalization reduces repeated data. The notes stop at third normal form.

FormRule in the notes
1NFEach cell holds one value. A column of “111, 222” is two phone numbers and is not atomic.
2NFNo partial dependency. With a primary key of more than one column, every other column must depend on the whole key, not on part of it.
3NFNo transitive dependency. A column depends on the primary key, not on some other column that itself depends on the key.

Second normal form only changes a table whose primary key is composite. A single-column key has no “part of the key” for a column to depend on. Third normal form is the case where, for example, a student row stores a college name and that college's city: the city depends on the college, and the college depends on the student. The city belongs with the college.

Transactions

A transaction is a group of changes that succeed or fail together. The notes name COMMIT and ROLLBACK. COMMIT makes the changes durable. ROLLBACK undoes the changes still open in that transaction.

START TRANSACTION;
UPDATE student SET city = 'Delhi' WHERE id = 1;
ROLLBACK;

The command-type list also includes SAVEPOINT, a named point you can roll back to without undoing the whole transaction:

SAVEPOINT before_update;
UPDATE student SET city = 'Delhi' WHERE id = 1;
ROLLBACK TO before_update;

ACID

PropertyMeaning
AtomicityAll of the transaction is applied, or none of it is. The notes say “all or nothing.”
ConsistencyThe database moves from one valid state to another. Constraints still hold when the transaction ends.
IsolationConcurrent transactions do not interfere with each other. This is the “no interference” idea in the notes.
DurabilityAfter a commit, the change remains even if the database process stops.
Isolation and durability are separate. The original notes attach “once done, follow values, no interference” to durability. No interference is isolation. Durability is the promise that a committed change is still there afterwards.

9. Command types and running a database

ClassStatements in the notes
DDL, data definitionCREATE, ALTER, DROP, TRUNCATE
DML, data manipulationINSERT, UPDATE, DELETE
DQL, data querySELECT, including WHERE, GROUP BY and ORDER BY
DCL, data controlGRANT, REVOKE
TCL, transaction controlCOMMIT, ROLLBACK, SAVEPOINT

TRUNCATE TABLE student; removes every row and is listed with the definition statements. DELETE can remove one row and is a manipulation statement. Some references treat SELECT as part of DML. These notes give it a separate query class, which is a useful way to remember it.

GRANT SELECT ON school.* TO 'reader'@'localhost';
REVOKE SELECT ON school.* FROM 'reader'@'localhost';

The grant and revoke lines are MySQL illustrations of the two DCL verbs. They are not in the original notes. Privileges are easy to make wider than you meant. Grant the smallest set the account needs.

What the notes list for DevOps

The last technical page names three operating topics and does not give commands for them.

  • Backup and restore. Take a copy of the database, and be able to load that copy back. In MySQL one common pair is mysqldump to write the backup and the mysql client to load it. The password should be prompted for, or read from a protected option file, not written into the command people share.
  • Tuning. The notes point at indexes, already covered above, and at connection pools. A pool is a set of open database connections the application reuses, instead of connecting again on every request.
  • How an application connects. The host, database name, user and password come from environment variables or a secret store. They do not belong in the source repository.
