These notes follow one path: how a device is addressed, how a message moves through the layers, how names and routes are found, and which ports and commands you use to check that path. The command examples are Linux.

1. IP addresses

An IP address is the notes' “home address” for a computer: the address of a network interface, so other hosts can send it packets. The example in the notes is 192.168.1.10.

172.16.x.x is only the start of that private block. The notes write 172.16.x.x. The private range is 172.16.0.0 through 172.31.255.255. 10.x.x.x and 192.168.x.x match the other two blocks as written.

2. Subnet masks, CIDR, MAC and DHCP

A subnet mask splits an IP address into a network portion and a host portion. Hosts with the same network portion are on the same local subnet. The notes' breakdown is:

IP:          192.168.1.110
Subnet mask: 255.255.255.0
Network:     192.168.1
Host:        110

That three-and-one split is true for this mask. A different mask moves the cut. 255.255.255.0 means the first 24 bits are the network.

CIDR is the short form the notes describe. 192.168.1.0/24 is the same mask: the /24 counts the network bits. Subnetting takes one network and divides it into smaller ones, for example several /26 networks cut out of a /24. The notes use /24 as the notation example, not as the only size subnetting can produce.

A /24 has 254 usable host addresses, not 256. The mask leaves 8 host bits, so there are 256 numbers. The all-zeros host is the network address (192.168.1.0) and the all-ones host is the broadcast address (192.168.1.255). Devices use the 254 addresses in between.

MAC address

A MAC address is the hardware address of a network card. The notes' example is 00:1A:2B:3C:4D:5E. It identifies the card on the local link. Routers do not forward a frame toward a MAC address on the far side of the Internet. The address can be changed in software, so the value on the wire is not always the one burned into the card.

DHCP

DHCP gives a device an address automatically. The notes' picture is a phone joining Wi-Fi and receiving 192.168.1.7. A typical lease also includes the subnet mask, the default gateway and the DNS servers. The notes name the IP address, which is the part you see first.

3. Gateway and NAT

The default gateway is the router address on your own subnet. Traffic for any other network is sent there. In the notes, the PC is 192.168.1.10 and the gateway is 192.168.1.1. If that router is down, other machines on 192.168.1.0/24 can still talk to each other. What fails is the path onward, including the Internet.

ip route show
route -n

ip route is the current Linux command. route is the older one. The same commands appear again with the other Linux tools. Day-to-day Linux is in Linux for Beginners.

NAT, in the notes, is what a home router does so private addresses can use the Internet. The router rewrites the private source address to its public address on the way out, and rewrites the reply back to the right private host. Many devices share that one public address. The router tells them apart by also translating port numbers. That port translation is the usual home-router form of NAT. The notes name the address translation.

4. The OSI model

The notes stack the work of a network into seven layers. On the way out, an application message moves down the stack and gains a header at each layer. On the way in, it moves up and those headers come off. The notes list the layers from the cable upward, then describe them from the application downward.

The Internet runs the TCP/IP model, which folds session and presentation into the application. TLS is drawn on the presentation layer in these notes. In a real stack it sits between the application and TCP. SSL is the older protocol that TLS replaced. Do not configure SSL 3.0. The padlock in a browser is TLS.

5. TCP, UDP, the handshake and sockets

TCPUDP
Trait in the notesReliable.Speed.
ConnectionConnection-oriented. A handshake comes before data.Connectionless. No handshake.
Loss and orderResends lost data and keeps order.No resend and no order in the protocol itself.
CostSlower, because it waits and keeps state. The notes say accurate.Less overhead. The notes say fast.
Used for, in the notesWeb (HTTP, HTTPS), email (SMTP), file transfer (FTP), SSH.Video calls, online games, DNS, streaming.

Those uses are the usual textbook pairing, not a rule. A video site can run over TCP. DNS queries usually use UDP on port 53, and the same port over TCP when the answer is too big for one UDP message. UDP is faster in the sense that it does not stop to recover a lost packet. The application has to notice the loss itself, if it cares.

The three-way handshake

TCP uses three messages to open a connection. The notes number them SYN, SYN-ACK, ACK.

Opening a TCP connection
1. SYN
client→2. SYN-ACK
server→3. ACK
client

After the third message, both sides may send data. Closing the connection is a separate exchange. The notes stop at the open.

Sockets and packets

A socket is one end of a conversation: an IP address plus a port. The notes' example is a browser at 192.168.1.10:54321 talking to a server at 142.250.190.14:80. Port 54321 is an ephemeral client port. Port 80 is HTTP. The connection is the pair of sockets.

A packet, in the notes, is a small piece of data sent across the network. At the transport layer the TCP piece is a segment and the UDP piece is a datagram. At the data-link layer the piece on the wire is a frame. The notes use packet for the general idea.

6. DNS, TLS and routing

DNS turns a name such as google.com into an IP address. The notes also describe private DNS as encrypting those queries and sending them to a resolver you choose, such as Google or Cloudflare, instead of the ISP's resolver.

Encrypted DNS hides the query, not every trace of the visit. DNS over TLS or DNS over HTTPS stops the ISP from reading the name inside the DNS message. The ISP can still see the IP address you connect to afterwards. “Private DNS” is also used for an internal name server that only answers inside a company network. The notes mean the encrypted-resolver kind.

TLS encrypts the bytes between a browser and a server. SSL is the predecessor, which the notes call the older version. ICMP, repeated here from the network layer, carries control messages. Ping is an ICMP echo request and echo reply. ICMP is also how a router reports that a destination cannot be reached, or that a packet's time to live ran out.

Routing

A routing table is the list a computer or router uses to choose the next hop and the interface. A static route is typed by an administrator. It does not repair itself when a link fails. The notes' example adds a route to 192.168.2.0/24 through 192.168.1.1:

ip route add 192.168.2.0/24 via 192.168.1.1

Dynamic routing means the routers tell each other about networks. The notes name three protocols.

ProtocolWhat the notes sayWhat “best path” means here
RIPDistance-vector. Hop count. More than 15 hops is unreachable.Fewest routers, not the fattest link. A one-hop slow link beats a three-hop fast one.
OSPFLink-state. Dijkstra's algorithm. Used inside one autonomous system.Lowest cost. The cost is usually derived from link bandwidth, so a faster link is preferred.
BGPPath-vector. Used between autonomous systems, which is how the Internet is glued together, and inside large networks.Policy. An operator can prefer a longer AS path because of a contract. Shortest hop count is not the rule.

7. Reverse proxies, load balancing, firewalls and CI/CD

A reverse proxy sits in front of the servers and accepts the client connection. Nginx, HAProxy and AWS Elastic Load Balancing are the notes' examples. The notes also call it an intermediate server between the user and the Internet. That second picture is a forward proxy, which acts for the client. A reverse proxy acts for the servers: the client thinks it is talking to the site, and the proxy talks to the backends.

The notes list what that front server is for: spread load, hide the backends, cache responses, and keep the site up when one backend fails.

Load balancing is the spreading part. Round robin walks the servers in turn. Least connections sends the next request to the server with the fewest open connections. The notes say “fewest active users.” The counter is connections, which is the right stand-in when one user can hold more than one.

Firewalls

A firewall rule allows or blocks traffic by port and address. Inbound is toward the server. Outbound is leaving it. The notes' tools are iptables, the low-level Linux command, and UFW, the Ubuntu frontend. The packet filter in current kernels is nftables. UFW and iptables are the two the notes show. The same UFW commands are in Linux for Beginners.

CI/CD, as the notes list it

9. Linux networking and firewall commands

CommandPurpose in the notes
ping google.comChecks that a host answers. The notes expand ping as Packet Internet Groper. That phrase is a backronym. The command sends an ICMP echo request.
traceroute google.comShows the path. Each probe increases the time to live by one, so the next router answers when the count runs out.
nslookup google.comAsks DNS for the name.
ifconfig and ip addr showShow the interfaces and their addresses. ip is the current command.
netstat -tulnListening TCP and UDP ports, numeric, without resolving names.
ss -tulnThe same view from the tool that replaced netstat. -t TCP, -u UDP, -l listening, -n numeric.
curl http://eg.comSends a request to a URL and prints the reply.
ip route show and route -nShow the routing table, including the default gateway.

A host that does not answer ping is not always down. Many networks drop ICMP and still accept TCP on port 443.

iptables and UFW

The notes' iptables lines list the rules, allow TCP port 22, and then set the input policy to drop everything else. The UFW lines turn the firewall on, allow SSH and HTTP, and show the result.

# iptables, as in the notes
sudo iptables -L -n -v
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -P INPUT DROP

# UFW. The notes write these as one allow line: "ufw allow 22, 80"
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw enable
sudo ufw status
Set the DROP policy after the allow rule, and keep the session you already have. iptables -P INPUT DROP discards packets that no earlier rule accepted. If the SSH allow is not already in the list, the connection you are using dies. Also allow packets that belong to a connection this host already opened, or replies to your own outbound traffic die too:
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

That established-state rule is the safety line the notes leave out. Put it, and the SSH allow, before the policy change. iptables rules disappear at reboot unless the distribution's save mechanism stores them. ufw enable on a remote host has the same trap: allow SSH first. On Ubuntu, UFW is the firewall already described in the Linux notes.
