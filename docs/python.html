1. Python revision

floor, ceil and division

Both functions come from the math module. The notes' examples are right. The labels next to them are swapped.

floor goes down. ceil goes up. The notes call floor an “approx max” and ceil an “approx low,” then give floor(3.7) → 3 and ceil(3.7) → 4. Those results are correct. floor is the greatest integer less than or equal to the value. ceil is the least integer greater than or equal to it. For a negative number the direction still matters: floor(-3.2) is -4, and ceil(-3.2) is -3.
import math
math.floor(3.7)   # 3
math.ceil(3.7)    # 4
OperatorWhat the notes sayIn Python 3
/Normal division, gives a decimal.True division. The result is always a float. 7 / 2 is 3.5. 4 / 2 is 2.0, not the integer 2.
//Floor division, does not produce a decimal.Floor division, toward negative infinity. Two integers give an int: 7 // 2 is 3, and -7 // 2 is -4, not -3. If either operand is a float, the result is a float: 7.0 // 2 is 3.0.

Dynamic typing

The notes contrast Python with C and Java. You do not write the type on the variable. The object you assign has a type, and that is checked when the line runs. count = 1 and later count = "one" are both legal. Python is still strict about operations: "1" + 2 is a TypeError, not a silent conversion.

List comprehension

A list comprehension builds a new list in one expression. The notes describe it as “this variable should contain these values from this loop, with this condition.” The figure in the PDF breaks the syntax into the output expression, the loop, and the filter:

squares = [n * n for n in range(6) if n % 2 == 0]
# [0, 4, 16]

That line is the shape of the figure. It is not a list copied from the original notes. n * n is the value that goes into the new list. for n in range(6) is the loop. if n % 2 == 0 keeps the even numbers.

*args and **kwargs

Both let a function take a variable number of arguments. The notes say *args is for passing them and **kwargs is for accepting them. In the definition, both accept whatever the caller sends.

def show(*args, **kwargs):
    print(args)     # a tuple of positional arguments
    print(kwargs)   # a dict of keyword arguments

show(1, 2, name="Ada")
# (1, 2)
# {'name': 'Ada'}

Sorting and Timsort

list.sort and the built-in sorted both use Timsort. The notes call it a combination of merge sort and insertion sort, with a worst case of O(n log n). That worst case is right. Timsort's advantage is the insertion-sort side: a run that is already ordered is cheaper, and the best case is O(n).

nums = [3, 1, 2]
nums.sort()            # sorts the list itself, returns None
copy = sorted(nums)    # a new list; nums is unchanged

sort is a list method. sorted works on any iterable and returns a new list. The notes name them together as functions.

Garbage collection

The notes describe the garbage collector as automatic memory management. It finds objects the program can no longer use and frees them, so you do not free memory by hand. In C, forgetting a free is a leak, and freeing too early is a crash. CPython's usual path is reference counting: when the last reference disappears, the object is freed immediately. A separate cyclic collector handles groups of objects that point at each other and would otherwise never reach a count of zero. The gc module is the interface to that cycle collector. The notes' reference list names it next to abc.

2. Functions, purity and LEGB

The notes separate a subroutine from a function. A subroutine is a named block you call again for one task. A function, in their wording, takes inputs of more than one kind and produces a concrete output. Python has one construct for both, def. What they are pointing at is whether the call is for its effect or for the value it returns.

A parameter is the name in the definition. An argument is the value at the call. The notes say the argument is passed “through the function definition.” It is passed through the call.

def greet(name):      # name is the parameter
    return "Hello " + name

greet("Ada")          # "Ada" is the argument

An interface, in the notes, is the set of actions an object offers: what it can do, not how. The implementation is the code that does it. Python has no interface keyword. Section 10 is where the notes build that idea with abstract base classes.

Meaning in the notes
Pure functionThe same arguments always produce the same result. A pure function also does not change anything outside itself. Printing, writing a file, or reading a global are side effects, so a function that does those is not pure even if the return value repeats.
Impure functionIt depends on, or changes, state that was not passed in as an argument. The notes call that a side effect.

LEGB

A namespace maps a name to an object. When Python sees a name, it searches in the order the notes' figure titles LEGB:

LEGB, first match wins
Local→Enclosing→Global→Built-in
  • Local: names assigned inside the current function.
  • Enclosing: names in the function that contains this one.
  • Global: names at the module level.
  • Built-in: names such as len and print.

Assignment creates a local name. To assign a global, or a name in the enclosing function, the function needs global or nonlocal. Those two words are the way out of the “read-only outer scope” rule. They are not drawn in the figure.

3. Algorithms and complexity

WordDefinition in the notes
AlgorithmA set of rules you follow to get a required output. It has to finish.
DataA raw value. The notes say it has no meaning until something structures it.
Data structureAn arrangement of data so an operation can reach it quickly. The notes' question to keep is why this structure, and the tool they name next is pseudocode.

Time complexity is the notes' name for measuring that cost by counting steps, not by the clock on one laptop. The figure runs from O(n²) toward O(1). The usual steps between those two ends are below. Toward O(1), the step count grows more slowly as the input grows.

Slower growth toward faster growth
O(n²)→O(n log n)→O(n)→O(log n)→O(1)

A priori and a posteriori

What the notes describe
A prioriTheoretical. You count steps from the algorithm and set the machine, the language and the clock aside. The notes say this assumes the external factors. The useful reading is that those factors are held out of the count.
A posterioriA measurement. You run the algorithm and record the time, and the memory, it actually used.

Time complexity, in the notes, is the number of steps to finish. Space complexity is the memory to finish. They split space into a fixed part and a variable part. The fixed part does not grow with the input: the code, and simple variables. The variable part does: the input itself, extra lists, and the call stack when recursion deepens.

Big O, Big Omega, Big Theta

NotationWhat the notes say
Big OAn upper bound. The notes use it for the worst case.
Big ΩA lower bound. The notes use it for the best case.
Big ΘThe bound is tight. If the notes can say both O(n log n) and Ω(n log n), they write Θ(n log n). The running time grows like n log n at both ends.
Worst case and Big O are not the same dial. Worst, best and average name which input you are talking about. O, Ω and Θ name how tight the bound is. You can put an O bound on the best case, and an Ω bound on the worst case. Intro notes, including these, pair O with worst and Ω with best because that is the pair people use most often.

4. Abstraction, ADTs and encapsulation

Data abstraction, in the notes, means showing the essential operations and hiding the representation. They connect it with modularity: the program splits into pieces you can use without reading the inside. A class is their representation of an abstract data type. An ADT is a set of values plus the operations on those values.

Two kinds of function support that, in the notes' wording from data-abstraction courses:

  • Constructor: builds a value of the abstract type.
  • Selector: reads information back out of it.

A concrete type is one whose representation you are allowed to see. A Python list is concrete: you know it is a list. The notes say an abstract object's representation is unknown to the caller. Unknown here means hidden, not that Python has forgotten it.

The notes' later components of abstraction in Python are abstract methods, concrete methods, abstract properties, and the rule that you do not instantiate the abstract class. Those are written out in the abstract-class section.

Level in the notesQuestion it answers
AbstractionDesign. Expose what is necessary and hide the rest.What can this object do?
EncapsulationImplementation. Put the data and the methods that touch it in one class, and block casual writes to the data.How is this data kept intact?

The notes' encapsulation principle is the pairing of private instance variables with public methods. The caller uses the method. The caller does not reach in and change the field.

5. Classes, constructors and __str__

The notes place the name with Monty Python's Flying Circus. Guido van Rossum, at Centrum Wiskunde & Informatica, released Python in 1991.

A class is a template that bundles data and functions. An object is one instance. Many objects can come from one class, each with its own attribute values. The notes' first example shares one class attribute:

class Dog:
    sound = "bark"

dog1 = Dog()
print(dog1.sound)    # bark

sound lives on the class. Every dog sees it until an instance assigns its own sound, which hides the class value for that instance only.

__init__ is the constructor the notes name. Python calls it when the object is created. self is the instance the method is running on. The name self is a convention, not a keyword. It has to be the first parameter.

class Dog:
    def __init__(self, name, age):
        self.name = name    # instance attribute
        self.age = age

    def bark(self):
        print(f"{self.name} is barking!")

    def __str__(self):
        return f"{self.name} is {self.age} years old"

dog1 = Dog("Buddy", 3)
print(dog1.name)
print(dog1)
# Buddy
# Buddy is 3 years old

Without __str__, print(dog1) looks like <__main__.Dog object at 0x...>. The notes describe that default. __str__ is what print and str() use.

Where it lives
Class variableOn the class, outside any method. All instances share it until one instance assigns the same name.
Instance variableOn self, usually inside __init__. Each object has its own.

A class variable that is a list or a dict is one shared object. Appending on one dog changes the list the other dogs see. A string or a number does not have that trap, because assigning self.sound = "woof" creates a new instance attribute instead of editing the class value.

6. Static methods, class methods and overriding

The notes say both a static method and a class method are bound to the class rather than to one instance. A static method receives neither the instance nor the class. A class method receives the class as cls.

class Dog:
    @staticmethod
    def info():
        print("Dogs are loyal animals")

    @classmethod
    def count(cls):
        print("there are many dogs of class", cls)

dog = Dog()
dog.info()     # static method, also callable as Dog.info()
Dog.count()    # class method
# Dogs are loyal animals
# there are many dogs of class <class '__main__.Dog'>

Method overriding is a subclass replacing a method the parent already has. The notes' pair is Animal and Dog:

class Animal:
    def sound(self):
        print("...")

class Dog(Animal):
    def sound(self):
        print("Woof")

The PDF shows class Dog(Animal) and the new sound. The parent class above is filled in so the snippet names the method it overrides.

7. Public, protected, private and properties

Encapsulation, repeated here for Python, means the class hides internal details and exposes what the caller needs. The notes use three spellings. Only one of them changes the name Python stores.

SpellingIntent in the notesWhat Python does
self.namePublic. Readable from anywhere. This is the default.The attribute is name.
self._ageProtected. For the class and its subclasses. Not a hard wall.Still just _age. The underscore is a warning to other programmers. emp._age works.
self.__salaryPrivate. Not for direct use outside the class.Name mangling. Inside Employee, __salary is stored as _Employee__salary. emp.__salary raises AttributeError. emp._Employee__salary still reads it.
A double underscore is not a lock. Mangling avoids accidental clashes in subclasses. It does not stop a caller who knows the class name. Methods such as __init__ and __str__ are not mangled: a name that also ends in double underscores is left as it is.
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.__salary = salary

    def show_salary(self):
        print("Salary:", self.__salary)

emp = Employee("Robert", 6000)
emp.show_salary()          # Salary: 6000

The notes' protected example is a subclass reading self._age. That works because _age was never hidden:

class Employee:
    def __init__(self, name, age):
        self.name = name
        self._age = age

class SubEmployee(Employee):
    def show_age(self):
        print("Age:", self._age)

emp = SubEmployee("Ross", 30)
emp.show_age()             # Age: 30

Getters and setters are how the notes give controlled access without a getName method from Java. @property reads. @name.setter writes.

class Employee:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        return self._name

    @name.setter
    def name(self, value):
        self._name = value

The PDF shows the two decorators. The __init__ that creates _name is added here so the property has a place to store the string.

8. Inheritance and super

A child class inherits attributes and methods from a parent. super() calls a method on that parent. The notes use it inside the child's __init__ so the parent can set the attributes it owns.

class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed
KindShape in the notes
SingleOne child, one parent.
MultipleOne child, more than one parent. class Employee(Person, Job).
MultilevelA child of a class that is itself a child.
HierarchicalSeveral children of one parent.
HybridMore than one of those patterns in the same tree.

With one parent, super() means that parent. With several, Python builds a method resolution order, a single list of classes, and super() continues at the next class in that list. That order is what keeps two parents that share a grandparent from running the grandparent's __init__ twice.

9. Polymorphism

Polymorphism is the notes' “many forms”: the same method, function or operator behaves according to the object it is given.

KindWhat the notes say about Python
Compile-time, overloadingA compiler would pick the method from the argument types. Python does not. It is dynamically typed, so there is no compile-time choice of one method among several with the same name. Default arguments, *args and **kwargs are how one function accepts several call shapes.
Run-time, overridingThe method that runs is the one on the object that was called, decided while the program runs. A child that defines sound replaces the parent's sound.
Built-inslen and max accept different types and use that type's own behaviour. len calls __len__.
FunctionsDuck typing. The function cares that the object has the method it calls, not that the object is a particular class.
Operators+ adds numbers and concatenates strings. That is operator overloading. The method behind + is __add__.
len("Ada")       # 3
len([1, 2, 3])   # 3
1 + 2            # 3
"A" + "da"       # Ada

10. Abstract classes, interfaces and binding

An abstract class is a template. The notes say you cannot construct it. It holds abstract methods that subclasses must implement. Python expresses this with the abc module.

from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def sound(self):
        pass

class Dog(Animal):
    def sound(self):
        return "Woof"

# Animal() raises TypeError
Dog().sound()    # "Woof"
PieceRole in the notes
Abstract methodDeclared, with no useful body, inside an abstract class. A subclass supplies the body. Until it does, the subclass is abstract too.
Concrete methodA normal method in the abstract class. Subclasses inherit it and can call it.
Abstract propertyA property marked abstract, so a subclass must provide it. The decorators are @property and @abstractmethod.
class Animal(ABC):
    @property
    @abstractmethod
    def species(self):
        pass

Trying to call Animal() raises TypeError. That is the instantiation rule in the notes.

Python has no interface keyword. The notes treat an abstract base class that contains only abstract methods as the interface: a contract, and no shared code. An abstract class in the wider sense may also contain concrete methods, which is the shared code. Both are written with abc.ABC.

Static and dynamic binding

The notes contrast Python with Java. Java can bind some calls when the class is compiled. Python almost never does.

  • The class body runs when the class statement finishes, so the method objects are created then. That is the closest thing the notes call static binding.
  • Which method runs for dog.sound() is decided at the call, from the class of that object. A child that defines sound is the one that runs. That is dynamic binding, and it is why overriding works with no extra keyword.
  • Overloading, several methods with the same name and different parameter lists, does not exist. One method uses defaults or *args and **kwargs.
