1. HTML concepts and the boilerplate

HTML is Hypertext Markup Language, the language that structures a page. The notes separate it from Markdown, and they separate a raw element from a component.

Markdown is a markup language. The notes set “markup languages” against Markdown, as if Markdown were something else. Markdown is a lightweight markup language. You write # and * in plain text, and a tool turns those symbols into HTML tags. HTML is the markup the browser actually builds the page from. The contrast that matters is weight: HTML spells the tags out, Markdown keeps the source short.
In the notes
ElementOne HTML building block, such as a heading or a button: the tags plus what they contain.
ComponentA reusable piece of interface, such as a React profile card, built from several elements and some behaviour. Components are the unit in the JavaScript and Express notes once the page moves into a framework.
UTF-8Unicode Transformation Format, 8-bit. The encoding that lets letters, symbols and other writing systems survive the trip to the browser. The charset meta tag declares it. A Content-Type header from the server overrides that tag, so the file, the tag and the header need to agree.
ARIAAccessible Rich Internet Applications. Attributes that tell assistive technology, such as a screen reader, what a custom widget is and how it behaves. A native element already carries that meaning. A button does not need role="button". Add ARIA when the native element cannot say what you mean.

Every HTML5 page in the notes starts from this boilerplate. lang tells the browser the language. The viewport meta stops a phone from laying the page out as a narrow desktop and then zooming out.

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Web Page</title>
</head>
<body>
    <h1>Main Heading</h1>
    <p>This is a paragraph inside the body.</p>
</body>
</html>

<!DOCTYPE html> is a declaration, not an element. It tells the browser to use the HTML5 parsing rules. The notes list it in the tag table. The browser records it as the document type, beside html, head and body, and it does not create an element you can style.

2. Tags and page structure

TagsPurpose in the notes
html, head, bodyThe root, the metadata, and the visible page.
h1 to h6Headings from most important to least. They describe the outline. They are not a font-size menu. Skipping from h1 to h4 because it looks smaller is what CSS is for.
p, span, divA paragraph, an inline wrapper, and a generic block. span sits in the line. div starts a new block.
aA link. href is the destination, another page or a section on this one.
imgAn image. alt is the replacement text when the image is not seen. It is not a tooltip. A decorative image gets an empty alt, so a screen reader skips it.
ul, ol, liA bulleted list, a numbered list, and one item.
form, input, buttonA form, a control, and a button. Inside a form, a button with no type submits. Use type="button" when the click should not send the form.
header, nav, main, footerSemantic regions: the banner, the navigation, the unique content of the page, and the close. The names do not, by themselves, put the banner at the top or the close at the bottom. CSS does the placement.

The layout section names the pieces a reader sees, on top of those tags. A menu, a title, a card, and a favicon, which is the small icon on the browser tab. The header or navbar holds the logo, the main links and a search field. The footer holds the copyright, a sitemap and social links. A sidebar is the vertical panel for a second menu or for filters. Breadcrumbs are the trail of where you are: Home, then Courses, then Web Dev.

3. Three ways to write CSS, and Bootstrap

CSS, Cascading Style Sheets, is the presentation. The notes give three places to put it.

KindWhere it lives
InlineOn the element, in a style attribute. The notes' paragraph is blue at 18px.
InternalA style element in head. The same rule, written once, applies to every p on that page.
ExternalA separate .css file, linked from the document. One file can style many pages.
<p style="color: blue; font-size: 18px;">This is blue.</p>

<style>
    p { color: blue; font-size: 18px; }
</style>

Bootstrap is the notes' example of an external stylesheet you did not write. It is an open-source set of classes for buttons, grids and navbars. It started at Twitter and is now its own project. You link the file from a CDN, which is the external method above, and use the class names instead of starting from an empty file.

4. The box model and units

Every element is a rectangle. From the inside out, the notes' four layers are the content, the padding, the border and the margin. Padding is inside the border. Margin is outside it, and it pushes neighbouring elements away. Adjacent vertical margins can collapse into one gap. The notes do not mention that collapse. It is why two stacked paragraphs sometimes have less space between them than the sum of their margins.

Figure 2, the box from the inside out
Content→Padding→Border→Margin
The default width is the content only. With box-sizing: content-box, a width of 100px plus 10px of padding on each side plus a 2px border on each side is 124px on the page. box-sizing: border-box puts the padding and the border inside the 100px. The notes name the four layers. They do not say which of them width includes. That choice is why a “100px” box overflows its column.

Units

UnitWhat the notes sayThe part that is easy to miss
pxA fixed size.A CSS pixel is the unit the layout uses. On a high-density screen it is not always one physical dot. Browser zoom scales px and rem together. The case where they diverge is the next row.
%Relative to the parent. Used for widths, heights and sometimes fonts.A percentage height needs a parent with a specified height. If the parent's height is auto, a percentage height does not resolve to a fraction of the screen.
emRelative to the parent's font size.That is true for font-size. For padding, margin and width, em uses the element's own computed font size. A child at 2em whose parent is 16px is 32px. padding: 1em on that child is 32px, not 16px.
remRelative to the root, the html element. The notes' default is 16px = 1rem.If the reader sets the browser's default font size to 24px, 1rem becomes 24px and the page scales. A size in px does not follow that preference. That is the notes' reason to prefer rem for type.
vw1% of the viewport width.100vw includes the width of the scrollbar on many browsers, so a full-width bar can spill sideways by a few pixels.
clamp()clamp(minimum, preferred, maximum).The preferred value is used only while it sits between the other two. The notes' padding is clamp(12px, 2vw, 24px): at least 12px, growing with the viewport, and never past 24px.

5. Specificity, inheritance, flex and grid

When two rules want different values for the same property, specificity decides. The notes' order, from strongest to weakest, is an ID (#message), then a class, attribute or pseudo-class (.warning), then an element or pseudo-element (p, h1). One ID beats any number of classes. When the counts are equal, the rule that appears later wins.

An inline style sits above that list. The notes start at the ID. A style attribute on the element beats an ID, a class and an element selector. !important sits above ordinary declarations from the same origin, which is why it is a poor way to “win”: the next override needs another !important. Neither the inline style nor !important is in the notes' three-step list.

Some properties pass from parent to child. Layout properties do not. The notes' split:

InheritedNot inherited
color, font-family, font-size, line-height, text-alignmargin, padding, border, width, height, background-color

A child often looks as if it inherited the background. It did not. Its background is transparent, so the parent's paint shows through. Set background-color on the child and the parent's colour stops showing there.

What it selectsNotes' examples
Pseudo-class, :An element in a state or a position.:hover, :focus, :first-child
Pseudo-element, ::A part of an element, or a generated box.::before, ::after, ::first-letter

Older CSS wrote :before and :first-letter with one colon. Browsers still accept that form for those old pseudo-elements. The double colon is how you tell a pseudo-element from a pseudo-class. :first-child stays a single colon. It is a pseudo-class.

Flexbox, in the notes, arranges items along one axis: a row or a column. Grid arranges them in rows and columns at once. Flexbox can wrap onto extra lines, so the result can look like a grid. You still only choose one main axis. Grid lets you size both axes.

6. The document object model

The notes read the three words this way. The document is the page the browser loaded. An object is an element represented so JavaScript can hold it. The model is the tree. Through that API, a script changes structure, style and text after the page has loaded.

Figure 3, the tree the browser builds
document→html→head
html→body→h1, p, …
MethodWhat it returns
getElementByIdThe one element with that id, or null.
querySelectorThe first element that matches a CSS selector, or null.
querySelectorAllEvery match, as a static list. No match is an empty list, not null. The list does not grow if you add elements later.
getElementsByClassNameThe elements with that class, as a live collection. It updates when the document changes. The notes list it next to querySelectorAll. Those two do not stay in step.
const soil = document.getElementById("soilMoisture");
const card = document.querySelector(".sensor-card");
PropertyWhat you read or write
textContentThe text, including text hidden with CSS. Setting it does not parse HTML. The notes' update is soil.textContent = "35%";
innerTextThe rendered text. Hidden text is left out. Reading it can force the browser to compute layout.
innerHTMLThe markup as a string. Setting it parses HTML and replaces the children.
Untrusted text does not belong in innerHTML. The notes say to prefer textContent for ordinary text. innerHTML will treat a string as markup. If that string came from a user or from an API, a <script> or an event-handler attribute in it runs as the page. That is the cross-site scripting case they name. textContent inserts the characters and does not parse them.

Style from script follows the same cascade as a stylesheet. element.style writes an inline declaration, which is the high-specificity form above. A class is easier to turn on and off, and it keeps the rule in the stylesheet:

soil.classList.add("status-required");
soil.classList.remove("status-normal");

classList.toggle adds the class when it is missing and removes it when it is present. classList.contains reports whether it is there.

7. Events, forms, fetch and when the script runs

EventWhen it fires
clickThe element was clicked. The notes log a message from the listener.
inputThe value changed, including each keystroke in a text field.
changeThe value was committed. For a text field that is usually when the field loses focus, not on every key. For a checkbox it is when the check changes.
submitThe form was submitted.
DOMContentLoadedThe HTML has been parsed. Images may still be loading.
button.addEventListener("click", function () {
    console.log("Button clicked");
});

On a form, .value is the text, .checked is a checkbox or radio, and .disabled turns a control off. preventDefault on submit stops the browser from navigating away and reloading. It does not save the data. If you still want it stored, the listener has to send it.

form.addEventListener("submit", function (event) {
    event.preventDefault();
    const name = document.getElementById("greenhouseName").value;
    console.log(name);
});

fetch

The notes use fetch to talk to a backend, and their example is a FastAPI server on 127.0.0.1:8000. The same HTTP shape is in the backend notes. response.ok is true for 200 through 299. A 404 still fulfills the promise, which is why the example checks ok and throws. That check is the point made in the Express notes. response.json() parses the body. JSON.stringify is the other direction: it turns a JavaScript value into JSON text for a request body. The example is a GET, so it parses a response and does not send one.

async function getSensors() {
    try {
        const response = await fetch("http://127.0.0.1:8000/sensors");
        if (!response.ok) {
            throw new Error("Request failed");
        }
        const data = await response.json();
        document.getElementById("soilMoisture").textContent =
            data.soil_moisture + "%";
    } catch (error) {
        console.error(error);
    }
}

When the script runs

defer on an external script downloads it while the HTML parses, then runs it after the parse, in document order, before DOMContentLoaded. async is the attribute people swap in by mistake. An async script runs as soon as it downloads, which can be before the parser finishes, and several async scripts do not keep their order. The notes do not name async. They name defer.

A selector returns null when the element is not in the tree yet. That happens when a script in head runs immediately and looks for a node that appears later in body. defer, or a listener for DOMContentLoaded, is how the notes wait.

<script src="js/dashboard.js" defer></script>
