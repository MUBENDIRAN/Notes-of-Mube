1. Variables, collections and callbacks

DeclarationWhat the notes say
constCannot be reassigned.
letCan be reassigned.
const locks the binding, not the contents. The notes' own array is declared with const and then changed with push. That is legal. const forbids users = somethingElse. It does not freeze the array or the object. Object.freeze is what blocks mutation, and even that is shallow.
const users = ["pavi", "rithik", "Mube"];
users[0]            // "pavi" — indexes start at 0
users.length        // 3
users.push("Raj")   // appends; users is now length 4

An array keeps values in order. The notes compare it with a Python list, which is the same idea as in the Python notes. An object keeps named fields. Their user is { username: "Mube", likes: 5 }, the shape of a dict.

FunctionArrow function
function add(a, b) { return a + b; }const add = (a, b) => a + b;

An arrow with a single expression and no braces returns that expression. Braces make a block, and a block returns only what you return. Otherwise the result is undefined.

An arrow function does not get its own this. The syntax table in the notes is right about return. The other difference matters in callbacks. A normal function receives this from the call. An arrow uses the this of the surrounding scope, has no arguments object, and cannot be used with new.

A callback is a function passed into another function. The notes' example calls it immediately with a name. Express middleware, in the later chapter, is the same shape: a function the framework will call when a request arrives.

function processUser(callback) {
  callback("Mube");
}
processUser((name) => console.log(name));  // Mube

2. Array methods, equality and null

MethodNotes' exampleResult
map[1, 2].map(n => n * 2)[2, 4]. One new value per element.
filter[1, 2].filter(n => n > 1)[2]. Always an array. No match gives [], not undefined.
find[1, 2, 3].find(n => n > 1)2, the first match. No match gives undefined.
reduce[1, 2, 3].reduce((a, b) => a + b, 0)6. The 0 is the starting total.

map and filter return a new array. They do not replace the one you called them on. The 0 in reduce matters: without a starting value, the first element becomes the start and an empty array throws.

Destructuring and defaults

const user = { username: "Mube", age: 20 };
const { username, age } = user;

const { role = "user" } = {};
console.log(role);  // "user"

The default is used only when the property is missing or undefined. null is a present value, so { role: null } leaves role as null. That is the rule the notes state. The PDF's example only shows the missing-property case.

Equality and truthiness

5 == "5" is true, because == converts the types first. 5 === "5" is false, because === compares the value and the type. Prefer === unless you have a reason to convert.

The notes' falsy values are false, 0, "", null, undefined and NaN. -0 and 0n are falsy too. Almost everything else is truthy, including [] and {}. An empty array is not a reason for an if to skip the block.

Optional chaining and ??

const post = { author: null };
console.log(post.author?.username);  // undefined, no throw

?. stops the property read when the value on its left is null or undefined. The notes' warning is the useful one: it prevents that crash. It does not check that the username is a real user, a string, or present in the database.

OperatorWhen the fallback is used
??Only null or undefined. 0 ?? 10 is 0. "" ?? "guest" is "".
||Any falsy value. 0 || 10 is 10. "" || "guest" is "guest".

Those four results are the notes' rule applied to the values they name. The PDF states the rule and does not print the four lines.

3. Modules and npm

ES modulesCommonJS
export const add = (a, b) => a + b;
import { add } from "./math.js";		module.exports = { add };
const { add } = require("./math.js");

Node treats a .js file as CommonJS unless package.json contains "type": "module", or the file is .mjs. The import lines in the notes run only in that mode. A .cjs file stays CommonJS either way.

package.json declares ranges. The lockfile records the tree. The notes give “the dependency tree” to both files. package.json is the project: name, scripts, and the ranges you asked for, such as ^4.18.0. package-lock.json is the exact versions npm resolved, including nested dependencies. Commit the lockfile so the next install can repeat that tree.
CommandWhat the notes use it for
npm init -yWrites a starting package.json without asking questions.
npm installInstalls the dependencies already listed. npm install express also adds a package to that list.
npm startRuns the start script. If that script is missing, npm falls back to node server.js.
npm testRuns the test script. There is no fallback command. A missing script is an error.
npm ciA clean install from the lockfile. It removes node_modules first and fails if the lockfile is missing or does not match package.json. It does not update the lockfile.

4. TypeScript

TypeScript is JavaScript plus a type system. The check happens before the program runs. The types are then erased, and what executes is JavaScript. The notes' annotation is let username: string = "MUBE";.

Form in the notes
AnnotationYou write the type. let score: number = 100;
InferenceTypeScript reads it from the value. let score = 100; is a number.

A union allows more than one type. After let id: string | number, both id = "MUBE 101" and id = 101 type-check. Before you call a string method, narrow it: typeof value === "string". typeof is the right test for the primitives in that union. It is a poor test for objects, because typeof null is "object".

interface User {
  name: string;
  age: number;
  email?: string;   // the property may be omitted
}

type ID = string | number;
let userID: ID = "U101";

The notes use an interface for an object shape and a type alias for a union. That split matches how the two forms differ. An interface describes an object and can be reopened later by another declaration of the same name. A type alias can name any type, including a union, a primitive, or a function. They are not interchangeable in every position, even though both can describe an object.

function identity<T>(value: T): T { return value; }
identity<string>("FACZ");
identity<number>(100);

T is the type chosen at the call. The notes write it out. TypeScript will also infer it from the argument, so identity("FACZ") is a string too. The explicit form is what the PDF shows.

5. Promises, combinators and async

StateMeaning in the notes
PendingStill running.
FulfilledFinished with a value.
RejectedFinished with a failure.

then takes the value. catch takes the failure. finally runs after the promise has settled, either way, and does not by itself replace the value or the error.

CombinatorWhen it settles
Promise.allFulfills when every promise fulfills. Rejects as soon as one rejects. The notes use it when you need all of the results and the requests can run together. The others keep running after that rejection. You just do not get their values from all.
Promise.allSettledWaits until every promise has fulfilled or rejected, then fulfills with one result per input.
Promise.raceSettles with whichever promise settles first, including a rejection.
Promise.anyFulfills with the first fulfillment. Rejects only when every promise rejects.

An async function always returns a promise. return 1 inside it becomes a fulfilled promise of 1. await pauses that function until the promise settles. If the promise rejects, await throws, so the handler is try/catch around the await, not only a catch on a chain you no longer have.

Blocking code holds the JavaScript thread until it returns. A long loop is blocking. A network call is not: other tasks can run while it is pending, and the callback runs later. The notes' timer rule is the same idea. setTimeout(fn, 0) does not run fn in the middle of the current function. It runs after that synchronous code finishes.

6. Express, middleware, Zod and fetch

Express is a Node framework for HTTP servers and APIs. The method and the request fields in the notes line up with the HTTP notes:

PieceRole
app.get / app.postRegister a handler for that method.
req.paramsValues taken from the path, such as /users/:id.
req.queryValues after the ?.
req.bodyThe parsed body. It stays empty until body-parsing middleware has run.
express.json()That middleware for a JSON body. Mount it before the route that reads req.body.
res.jsonSends a JSON response and sets the content type.

The lifecycle diagram in the PDF is this order:

Request path in the notes
Client→Gateway→Middleware→Route
Service→Database→Response

The route handler owns the HTTP request and response. The service owns the business rule. Middleware is the shared step: authentication, logging, validation. A middleware function sees req and res. next() hands the request to the next function. An error-handling middleware is written (err, req, res, next). Express treats a function as an error handler when it has those four parameters, so dropping next because it looks unused changes which kind of middleware you registered.

A middleware that neither answers nor calls next leaves the request hanging. That is the notes' warning. The client waits until it times out. Validate on the server as well. A check in the browser can be skipped. The notes' example is the post text: it has to be present, and it has to fit the length you allow, before anything is saved.

Zod

TypeScript removes types before the program runs, so a JSON body is untyped data at the route. Zod checks that data while the request is happening. safeParse returns an object whose success field is the check the notes tell you to read. parse throws instead of returning that object.

const parsed = schema.safeParse(req.body);
if (!parsed.success) {
  return res.status(400).json({ error: parsed.error.issues });
}
// parsed.data is the value the schema accepted

The PDF says to check result.success. It does not print this handler. 400 matches the invalid-input status in the HTTP notes. Zod's own examples often use the issues list the same way.

fetch

A 404 does not reject fetch. fetch returns a promise, and response.ok is true only for status codes 200 through 299. A 404 or a 500 still fulfills the promise. The promise rejects when the network fails: DNS, a dropped connection, or an abort. After a successful HTTP round trip you still have to look at response.ok before trusting the body. response.json() is itself asynchronous. AbortController cancels a request that is still in flight.

7. Tokens, the gateway and signing

An access token is the short-lived credential a client sends to a protected API. A refresh token is how the notes get a new access token without asking the user to sign in again. The refresh step is a separate, controlled call. It is not a second copy of the access token.

A JWT payload is readable. Signing is not encryption. The notes say the payload is not automatically encrypted. The three segments are Base64url text. Anyone who has the token can decode the middle segment and read the claims. The signature tells you whether the bytes changed after they were signed. It does not hide them. Do not put a password or a secret in the payload.

The gateway diagram is the trust boundary:

Gateway trust, the path in the notes
Client→Public gateway→Internal service

The gateway checks the JWT, strips client-supplied identity headers, then adds its own.

The gateway is the only public entrance. On a protected route it verifies the JWT. It deletes any x-user or x-gateway-secret the client sent, because a caller can set those headers to whatever they like. It then adds its own x-user, which the notes describe as Base64-encoded JSON of the identity, and a shared secret. An internal service accepts x-user only together with that secret. Base64 is an encoding. It is not encryption, and it is not proof that the header came from the gateway. A service that is reachable without the gateway cannot treat x-user as identity.

Hashing and signatures

What the notes are naming
SHAThe Secure Hash Algorithm family. The notes say “Secure Hashing Algorithm.” A cryptographic hash is one-way: the digest does not give you the original input back, and the same input always hashes to the same digest. SHA-256 and SHA-512 are the ones paired with the signatures below. The name is a family, not a single function.
HMACHash-based Message Authentication Code. A secret is mixed into the message, then a hash is taken. Someone without the secret cannot produce a matching code. This still is not encryption. The message can sit beside the code in the clear.
HS256, HS512HMAC with SHA-256 or SHA-512. One secret both creates and checks the signature. The notes call this the single-system case. Every service that can verify the token can also mint one, because it holds that secret.
RS256RSA with SHA-256. RSA is Rivest–Shamir–Adleman. The private key signs. The public key only verifies, and it can be shared. This is the notes' case when more than one system must check a token and must not be able to create one.
