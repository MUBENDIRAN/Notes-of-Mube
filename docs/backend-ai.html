1. Environment and the shell

Before the backend code, the notes put you in a command-line shell, a Python virtual environment, and a package installer. The Linux notes cover the shell in more detail. The names here are the ones this chapter lists.

ShellWhat the name refers to
BashThe Bourne Again Shell. It is the default interactive shell on many Linux systems.
ZshA Bash-like shell. It is the default on current macOS.
FishA shell with its own syntax. It is not a POSIX sh.

The PDF lists the seven names. The second column is the usual meaning of each name, not a sentence copied from the notes.

venv is a module that ships with Python. It creates a directory with its own interpreter and its own installed libraries, so one project does not overwrite another's packages. Creating and using one is covered with the rest of the language in the Python notes.

uv is a Python tool, not a manager for every package on the machine. The notes call pip the old package manager and uv the new manager “for all packages.” Pip is still the installer that comes with Python. uv, from Astral, is a newer installer and project manager for Python: it can install libraries, lock them, and install Python itself. It does not replace apt, npm, or the system package manager.

2. Agile and DevOps

Agile, in the notes, is iterative delivery, collaboration, customer feedback and room to change the plan. A sprint is the short cycle. The notes put it at one to four weeks. DevOps is the name they give the bridge from writing the code to running it: automate the build, the test, the deploy and the monitor. Their line is that Agile sets the rhythm and DevOps supplies the speed.

IdeaIn the notesHow they tie it to DevOps
SprintA short cycle that ships a small usable slice.Plan the automation and the pipeline for that slice.
ScrumSprints, a daily stand-up, a review and a retrospective.Line deploys and test environments up with the sprint.
KanbanA board: to do, in progress, done.The same shape shows up on a pipeline or an issue tracker.
User storyOne piece of behaviour, written from the user's side.The story can name the environment or the automation that feature needs.
BacklogThe ordered list of work not started.Infrastructure and automation tasks live there too.
Stand-upAbout fifteen minutes on progress and blockers.Builds, deploys and automation health belong in that update.
VelocityHow much work a sprint finished.A rough cap on how much infrastructure work the next sprint can take.

The notes' four pillars are continuous feedback through monitoring, iterative delivery through a CI/CD pipeline, collaboration in shared tools, and adaptability through infrastructure as code. The tools they name are Jira, Jenkins and GitHub Actions. GitHub Actions is written up in the Git and GitHub Actions notes.

The tools they put next to a REST API are Postman and curl for calling endpoints, NGINX and Apache in front of the API, Docker and Kubernetes for containers, and Jenkins, GitHub Actions or GitLab CI for the pipeline. Docker runs a container. Kubernetes is the orchestrator that schedules many of them. That split is the subject of the Docker notes. curl's name is short for “client URL.”

3. Routes, URLs and status codes

In these notes an API is the set of routes the backend exposes over HTTP: a method, a URL and the function that runs. A route is that pair. Their example is GET /health calling health_check(), the path a load balancer or a monitor hits.

The URL figure splits an address into the usual parts:

URL anatomy, the shape of the figure
scheme→host→port→path→query→fragment

https://api.example.com:443/users/123?active=true#profile

RequestResponse
Method, path, headers, and a body when the method carries one.Status code, headers, and a body.

CRUD and the method contract

MethodNotes' exampleContract worth keeping
GETRead /api/users. Parameters sit in the URL. The notes say it has no side effects and can be cached.Safe and idempotent. Repeating it does not change the resource. Caches are allowed to store it.
POSTCreate /api/users. The body is JSON.Not idempotent. Two identical calls can create two users.
PUTUpdate /api/users/123.The notes say “update existing data.” A PUT replaces the representation. Sending the same body again leaves the resource in the same state, so it is idempotent.
PATCHPartial update of /api/users/123.Only the fields you send change. A second call is not guaranteed to be a no-op unless the patch itself is written that way.
DELETERemove /api/users/123.Idempotent. Deleting a resource that is already gone is still “gone.”
The POST line in the notes is a double negative. It says calling twice “≠ not same result.” Read it as: calling POST twice does not have to produce the same result. That is what “not idempotent” means.

Status codes in the notes

CodeHow the notes use it
200OK. An empty list is a fair 200 for a search that matched nothing.
201Created. The resource now exists.
400Bad Request. The input is invalid.
401The notes gloss this as “no valid authentication.”
404Not Found. Prefer this when the client asked for one specific resource and it is missing.
422The notes call this a validation error. FastAPI returns it when the body or the parameters fail validation. The status means the server understood the syntax and still cannot carry out the instruction.
500Internal Server Error. The failure is on the server.
401 is a missing or rejected credential. 403 is a refused permission. The status is named Unauthorized, which sounds like “you may not do this.” What it asks for is authentication: send a valid login, token or other credential. Once the server knows who you are and still refuses the action, the code is 403 Forbidden. The notes do not list 403. The two codes get mixed up constantly.

4. REST constraints

REST is Representational State Transfer, an architectural style for networked applications. The notes describe it as the way web APIs talk over HTTP. HTTP is the protocol people usually use. The style is the set of constraints, not the protocol.

ConstraintWhat the notes say
Client–serverThe interface and the data store are separate. A mobile app can call an API hosted on AWS.
StatelessThe server does not remember the client between requests. Each request carries its own authentication, and the notes' example is a JWT.
CacheableA response may be stored and reused. The header they name is Cache-Control.
Uniform interfaceResources are named in a standard way. /users/123 is user 123.
Layered systemThe client need not know it is talking to a gateway. Their example is NGINX in front of the app. Reverse proxies are also in the networking notes.
Code on demandThe server can send code for the client to run. The notes say this is usually avoided.
Stateless does not mean the database forgets the user. The server stores resources. What it must not store, between requests, is client session state. A JWT is one way to carry identity in the request itself. A session id that only works because the server kept a session object is the stateful pattern. Code on demand is the optional constraint. The other five are the ones a REST API is expected to keep. A uniform interface is also more than a URL shape: the message identifies the resource, the representation is what the client sends and receives, and the message says how to process it.

5. JSON, FastAPI and the ASGI server

JSON is a language-independent text format for structured data. The notes say “independent-language,” which is that idea. FastAPI turns Python objects into a JSON response and turns a JSON body back into Python objects. Their payload is:

{
  "ID": 123,
  "Name": "Mube",
  "role": "Engineer"
}

The reasons the notes give for FastAPI are speed of building the API, interactive docs from Swagger UI, validation without a hand-written checker, and async handlers. Validation here checks types and shape at the edge of the API. It does not replace the parameterized queries in the next database chapter. When validation fails, FastAPI responds with 422.

Uvicorn is the ASGI server the notes name. ASGI is the Asynchronous Server Gateway Interface, the async successor to WSGI. A WSGI app is a synchronous callable. ASGI can hold a connection open, which is what WebSockets need, and it can await network calls instead of blocking a worker.

Gunicorn manages processes. Uvicorn workers run the app. The notes compress this to “Gunicorn → Uvicorn update: Manager, handles I/O, process management.” Gunicorn is the process manager: it starts workers, restarts them and listens for shutdown. Each worker is a Uvicorn worker that speaks ASGI to FastAPI. The current Uvicorn deployment guide says the old uvicorn.workers worker class is deprecated, and the replacement package is uvicorn-worker. For local work the notes' path is still Uvicorn itself. The Gunicorn page linked from the PDF now 404s. The current deploy guide is the one in the references.

6. Filtering, sorting, pagination and decoupling

List endpoints take the extra choices as query parameters, so the path stays stable. The notes' three are a field filter such as category=electronics, a sort such as sort-by with sort-order=desc, and a page such as page=2 with size=20. In FastAPI a simple function parameter that is not part of the path becomes a query parameter. An optional one is the notes' Optional[...].

They want the filter, the sort and the page applied in the database, not after the application has loaded every row. That is what keeps memory down. The offset formula they give is:

offset = (page - 1) × limit

limit is how many rows to return. offset is how many to skip. Page 1 starts at 0. Page 2 with a size of 20 starts at 20.

The formula is right, and a large offset is still expensive. The database often still walks the skipped rows. A maximum page size caps how much one response holds. It does not make “page 5000” cheap. The notes' SQL reference, Use The Index, Luke, is about that cost and about paging with a key instead of an offset.

The notes also contrast a dynamic query, which fetches one row by something like a serial number, with a static query, which orders or searches by a fixed field such as type. That pair is about which rows you want. “Dynamic SQL” in the next chapter is a different phrase: it means the statement text is assembled in code.

Decoupling, here, means the handler turns a database row into the dictionary the API promised. The frontend depends on that contract. You can change the table without changing the client, as long as the JSON stays the same. Sending the row through unchanged leaks the table's column names into the API.

7. SQL safety and where NoSQL fits

The rule in the notes is absolute: do not paste user input into the SQL text. Pass it as a bound parameter. A dynamic statement, one the code builds up for optional filters, still binds every value. The notes record a real mismatch: the number and the order of placeholders have to match the parameter list, or the driver raises an error. The SQL notes cover the language itself.

# The value is data. It is not part of the statement text.
cursor.execute(
    "SELECT id, name FROM users WHERE name = %s",
    (name,),
)
A placeholder cannot stand in for a column or an ORDER BY. Parameters bind values. sort_by=name has to become a column name in the SQL text, and a client-supplied column name is an injection point if you concatenate it. The notes' fix is a whitelist. A set answers “is this allowed?” A dict answers that and maps the public name onto the real column, which is useful when the API name and the column name differ.
columns = {"name": "name", "created": "created_at"}
order = columns.get(sort_by)
if order is None:
    # reject the request; do not build the ORDER BY
    ...

Every public limit needs a ceiling. The notes give three reasons: memory, a large scan, and a denial of service from a client that asks for everything. Close the database connection when the request is done, so you do not leak connections, hold locks, or exhaust the server. A pool is the usual form of that rule: the request returns the connection to the pool instead of opening a new one every time.

NoSQL, in the notes, fits high scale, a schema that changes, event data, caching, and access patterns you can predict, when those matter more than joins and ad hoc queries. It is not a faster replacement for every relational table.

8. HTML, HTMX, React and WebSockets

ApproachWho builds the page
Jinja2The server fills a template and sends HTML. That is server-side rendering.
HTMXThe browser asks the server for a fragment and swaps that fragment into the page.
ReactJavaScript in the browser builds the interface from JSON. That is client-side rendering.
HTMX is a JavaScript library. The notes say it updates part of the page “without JS.” You do not write the client script. The library, which is JavaScript, sends the request and swaps the HTML the server returns.

A WebSocket stays open. Either side can send a message when an event happens, so the browser does not have to poll. The notes' uses are chat and games. The arrow in the PDF, both directions, is that difference from one HTTP request waiting for one response.

9. Roles, sampling and training

RoleIn the notesThe usual meaning
SystemHow the model should behave.Instructions that sit above the conversation: tone, rules, the task.
UserThe user prompt.What the person sent.
Assistant“Previous chat data.”The model's own earlier replies. The user's earlier turns stay on the user role. Together, those messages are the chat log the notes say you can hand to a library such as LangChain on the next call.

Temperature, in the notes, runs from 0, “no creative,” to 2, “high creative.” On OpenAI's API that range is real: higher temperature flattens the distribution, so less likely tokens get picked more often. Lower temperature concentrates on the likely tokens. It does not make a wrong answer correct. It makes the likely continuation more repeatable. Some models, including some reasoning models, do not accept a custom temperature at all.

Top-p is not a confidence score. The notes gloss top-p as “how confident the choice must be,” with 90% as the example. Nucleus sampling keeps the smallest set of tokens whose probabilities add up to p, then samples inside that set. Top-k is the other knob they name: keep only the k most likely tokens. OpenAI exposes temperature and top-p, and recommends changing one of them, not both. Top-k is a common setting on other runtimes. It is not an OpenAI chat parameter.
ApproachWhat changesThe notes' tradeoff
Prompt engineeringInstructions and small documents go in the prompt. The weights stay as they are.Easy to try. You pay the context on every call, and the window is finite. Fits small documents and experiments.
Long contextThe model reads a large document directly. No vector database.Better chance of seeing the whole document. Slower, more expensive, and still bounded by the window. Fits reports, books and papers.
Fine-tuning with LoRA, QLoRA or UnslothTraining examples teach a style or a format.Fast at response time, consistent voice, structured output. When the facts change you retrain, and you need data and a GPU. The notes' uses are a company voice and structured output.
Continued pretrainingMore training on domain text, on top of an existing model.Deeper grasp of the field's language. Expensive, and it wants a large domain corpus. The notes name medicine, law, science and finance.
Full pretrainingTrain on a massive corpus so the knowledge is in the weights.The strongest general model, and the least practical for a product team. This is how foundation models are made.

LoRA does not rewrite every weight. It trains small adapter matrices and leaves the base model frozen. QLoRA does that on a quantized base model, so the frozen weights take less memory. Unsloth is a library that trains those adapters faster. The notes are right that the behaviour changes and that new facts still require another training run. They are not baked in the way a pretraining corpus is.

10. Retrieval and knowledge graphs

RAG is how the notes answer from documents that change, without another training run. The flowchart in the PDF is the usual pipeline:

Vector RAG, the flow the figure describes
Chunk the documents→Embed→Vector store
Embed the question→Nearest chunks→Prompt the model→Answer

Their example is the question “How many vacation days do employees get?” The chunk that answers it says “20 annual leave.” A vector search can match vacation to annual leave. A keyword search for “vacation” misses that page.

MethodHow it finds textTradeoff in the notes
Vector RAGChunks live in a vector database such as Chroma or FAISS. The closest chunks go into the prompt.Documents can change without retraining. Cheap to start, and it scales to a large collection. If the retrieval misses, the answer is wrong, and the model does not keep the fact afterwards. Fits policies, manuals and PDFs.
Vectorless RAGKeywords, metadata, SQL, BM25, a file path, or reading a document directly.No embedding model and no vector database. It misses a page that uses a different word. Fits a small collection, a structured table, an FAQ, or an exact term.
Knowledge graphFacts and relationships are edges. The model queries the graph.Strong on connected facts. Harder to build and keep current than a chunk index. The notes name enterprise, medical and finance data.

11. Agents, memory, MCP and browsers

Agentic AI, in the notes, means the model chooses tools before it answers: retrieval, an API, SQL, search, code. That can finish a task that needs several sources. It is also slower, more expensive and harder to operate. A chatbot answers. An agent is supposed to carry out the task. The loop they write is think, act, observe, repeat. LangGraph is the orchestration tool they name for a workflow that is more than one step.

The agent loop in the notes
Think→Act→Observe→Repeat
MemoryWhat the notes store there
Short-termThe current chat.
Long-termInformation kept outside the model, so a later session can see it.
SemanticFacts.
EpisodicPast events.
ProceduralHow to do a task.

The tools they attach to that stack:

ToolRole the notes give it
Mem0The notes say “short memory.” Mem0 is a memory layer that stores facts across sessions. That is long-term memory, not the current turn. The current turn is already in the message list.
ZepChat memory.
ChromaA vector database the notes recommend for getting started.
QdrantA vector database they mark for production.
WeaviateA vector database they mark for enterprise. All three store vectors. The split is how the notes would run them, not a rule that one of them cannot be deployed smaller or larger.

MCP, the Model Context Protocol, is the notes' standard way for a model to call an external tool. Their analogy is USB for AI. FastMCP builds a server. The MCP SDK is the official library. Smithery is where they would look for a server someone else published. MCP Inspector debugs one.

Browser and computer use is the model clicking, typing, scrolling and reading, the way a person would. Browser Use, Stagehand and Skyvern are agent layers. Playwright and Selenium are the browser drivers underneath that kind of tool. A coding agent, in the notes, reads, plans, edits, tests, fixes and repeats. The projects they name are OpenHands, Cline, Aider and Goose.

12. Evaluation, observability and inference

Evaluation asks whether the answer is right. Observability asks why a particular request behaved the way it did. The metrics they list are latency, cost, tokens and success rate. The tools are Langfuse, Arize Phoenix, OpenTelemetry and Braintrust. OpenTelemetry is the general tracing standard. The other three are products aimed at LLM traces and evals, and they can export through that standard.

Training is when the model learns. Inference is when it answers. A token is the small text unit the model reads and writes. Latency is how long the answer takes. Throughput is how many requests per second the server finishes. Quantization stores the weights in fewer bits, so the model is smaller and often faster, with some loss of quality.
